# Known limitations

🌐 **English** · [Português](../pt-BR/limitations.md) · [Italiano](../it/limitations.md)

Everything below is a conscious trade-off or a known gap, not a hidden bug. Each item says what
happens today and how it would be fixed. Keep this page up to date in all three languages.

## Functional scope

| #   | Limitation                                                  | Today                                                                                                                                                                                                                  | Fix                                                                                                                                     |
| --- | ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| F1  | **Stores are connected by hand, not installed as an app**   | Multi-store works (one `Store` per shop, per-store data and webhook secret), but a store is added in the Stores page by pasting its webhook signing secret, and its webhooks are created by hand in the Shopify admin. | Public app with OAuth install: the app stores the shop's token and registers its webhooks automatically (Path B in `shopify-setup.md`). |
| F2  | **One currency per store, no cross-store totals**           | Amounts are formatted in the store currency (set when connecting the store). Orders in another presentment currency are summed in the shop currency Shopify sends; there is no view that adds up several stores.       | Convert with daily FX rates if a consolidated multi-store dashboard is needed.                                                          |
| F3  | **No historical backfill**                                  | Only orders created or updated after the webhooks are registered are imported.                                                                                                                                         | Backfill job using the Admin GraphQL API (bulk operations).                                                                             |
| F4  | **Two compliance webhooks are acknowledged, not processed** | `customers/redact` anonymizes the customer. `customers/data_request` and `shop/redact` return 200 and are only logged.                                                                                                 | `data_request`: export the customer's data for the merchant. `shop/redact`: delete all data of the shop.                                |
| F5  | **Not every order event is handled**                        | Refunds arrive through `orders/updated` (`current_total_price`); `refunds/create`, `orders/delete` and `customers/merge` are not subscribed.                                                                           | Add handlers with the `shopify-webhook-topic` skill.                                                                                    |
| F6  | **Guest orders are not linked to customers**                | An order without `customer` is stored with no customer and does not count in any LTV.                                                                                                                                  | Match by normalized email, with care for LGPD.                                                                                          |
| F7  | **Global segment rules**                                    | `em_risco` uses one threshold (`CRM_RISK_DAYS`, default 60) for every customer and product.                                                                                                                            | Thresholds per category or per customer purchase cycle (median interval between orders).                                                |
| F8  | **LTV is revenue, not margin**                              | `current_total_price` includes shipping and taxes; costs and margins are not modeled.                                                                                                                                  | Import product costs and compute contribution margin.                                                                                   |
| F9  | **Abandoned carts depend on Shopify webhooks**              | Carts come from `checkouts/create`/`checkouts/update`. A cart is "abandoned" while `completed_at` is empty, with no time threshold, and carts that never reach the checkout (no contact info) are invisible.           | Ignore checkouts younger than ~1 h in KPIs; add the `abandonedCheckouts` Admin API query as a backfill.                                 |

## Reliability and scale

| #   | Limitation                               | Today                                                                                                                                                                                                                                 | Fix                                                                                                                        |
| --- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| R1  | **Synchronous webhook processing**       | Processed inside the request in one short transaction (ADR 0003). If the database is down, the endpoint returns 500 and Shopify retries a limited number of times; subscriptions that keep failing are eventually removed by Shopify. | Queue (Inngest/QStash/SQS): acknowledge immediately, process with retries and a dead-letter queue.                         |
| R2  | **Out-of-order guard is not race-proof** | The `updated_at` check reads then writes. Two deliveries of the _same_ order processed at the _same_ instant could still apply in the wrong order (duplicates are impossible thanks to the unique constraints).                       | `SELECT … FOR UPDATE` on the order row, or a conditional update `WHERE shopifyUpdatedAt < :new`.                           |
| R3  | **Login rate limit is per instance**     | Better Auth keeps counters in memory (10 sign-in attempts/min/IP). On Vercel each serverless instance has its own counter.                                                                                                            | `rateLimit.storage: "database"` or Redis (Upstash).                                                                        |
| R4  | **No caching of CRM queries**            | Dashboard and lists query Postgres on every request. Fine for thousands of customers.                                                                                                                                                 | `use cache` + `cacheTag` invalidated by the webhook, or materialized views.                                                |
| R5  | **Migrations run in the Vercel build**   | `prisma migrate deploy` runs before `next build`; a failing migration fails the deploy (the previous version stays online). A destructive migration would break the rollback.                                                         | Keep migrations additive (expand/contract, see skill `prisma-migration`); at scale, migrate in a dedicated CI step.        |
| R6  | **Pinned Supabase CA expires in 2031**   | The app verifies Supabase's TLS against the Supabase Root 2021 CA embedded in `lib/db-adapter.ts` (valid until 2031-04-26). If Supabase rotates its CA earlier, database connections fail with a certificate error.                   | Update `SUPABASE_ROOT_CA` from the dashboard (Database → SSL Configuration) and check the SHA-256 fingerprint.             |
| R7  | **No rotation for `STORE_SECRETS_KEY`**  | Per-store webhook secrets are encrypted with AES-256-GCM using one key. Changing the key makes the stored secrets unreadable (webhooks return 401) until each secret is re-entered.                                                   | Use the `v1.` prefix of the ciphertext for key versioning: decrypt with old keys, re-encrypt with the new one in a script. |

## Authentication and access

| #   | Limitation                                            | Today                                                                                                                                                                 | Fix                                                                                         |
| --- | ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| A1  | **No password reset or email verification**           | There is no email provider; users are created by the seed (or by an admin in the database).                                                                           | Configure an email provider (Resend) and Better Auth's reset/verification flows.            |
| A2  | **No roles**                                          | Every signed-in user sees every customer and can use the agent.                                                                                                       | Better Auth admin/organization plugin with roles (e.g. viewer, analyst).                    |
| A3  | **GitHub login only on the production domain**        | The OAuth app has one callback URL; on preview deployments only email/password works.                                                                                 | One OAuth app per environment, or Better Auth's OAuth proxy plugin.                         |
| A4  | **Preview deployments share the production database** | In the live deployment, the _Preview_ environment variables point to the same Supabase database as production (demo data only), so previews read and write that data. | Use a Supabase branch or a staging database for Preview before handling real customer data. |
| A5  | **No per-store permissions**                          | Every signed-in user sees every store and can connect, update or remove stores.                                                                                       | Organizations/roles (Better Auth plugin) with a membership table between users and stores.  |

## AI agent

| #   | Limitation                                        | Today                                                                                                                                                                   | Fix                                                                                                         |
| --- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| G1  | **No automated evaluation**                       | Quality was checked manually; there is no eval set measuring accuracy of answers and drafts.                                                                            | Eval set of real questions with expected tool calls and graded answers, run in CI on prompt changes.        |
| G2  | **Single-turn**                                   | Each question is independent; there is no conversation history in the UI.                                                                                               | Store the thread in `agent_runs` and resend it (append-only).                                               |
| G3  | **Quota is a rolling 24-hour window**             | `AGENT_DAILY_LIMIT` counts runs in the last 24 h per user. Tokens are recorded, but there is no cost alert or budget.                                                   | Monthly budget per user/org and alerts on `agent_runs`.                                                     |
| G4  | **Prompt injection is mitigated, not impossible** | Store data (names, product titles) reaches the model. The tools are read-only, so a successful injection cannot write or send anything, but it could distort an answer. | Keep tools read-only; sanitize/truncate free-text fields; human review stays mandatory.                     |
| G5  | **Data leaves the company**                       | First names and purchase history are sent to the Anthropic API.                                                                                                         | In a real company: data processing agreement and documented LGPD legal basis; consider zero data retention. |

## Interface

| #   | Limitation                                     | Today                                                                                                                                                                                                                        | Fix                                                                                               |
| --- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| U1  | **Unknown customer returns HTTP 200**          | `/customers/<invalid-id>` renders the 404 page, but with status 200: with streaming (Cache Components) the status is sent before the data is read.                                                                           | Validate the id format before streaming, or accept it (the page is behind login and not indexed). |
| U2  | **Translations are maintained by hand**        | The UI is in English (default), Portuguese and Italian, with typed dictionaries and a test that checks keys and placeholders. Store data (product titles, names) is shown as received; the agent answers in the UI language. | Translation management (e.g. Crowdin) if more languages are added.                                |
| U3  | **Accessibility not audited**                  | Semantic HTML, labels, `aria-live` and focus states are in place, but there was no formal audit.                                                                                                                             | Axe checks in Playwright + manual screen-reader pass.                                             |
| U4  | **Language lives in a cookie, not in the URL** | URLs have no locale prefix: `proxy.ts` rewrites them to `/[locale]/…` from the `oh_locale` cookie. A link like `/it/customers` sets the language once and redirects. Changing language reloads the page.                     | Locale-prefixed URLs if pages ever become public (SEO); not needed behind login.                  |

## Local development

| #   | Limitation                                        | Today                                                                                                                                                                                                                         | Fix                                                                                  |
| --- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| D1  | **`prisma dev` accepts one connection at a time** | The embedded Postgres (PGlite) mixes protocol messages with concurrent connections (`bind message supplies N parameters…`). Locally `DATABASE_POOL_MAX=1`; production uses 5.                                                 | Use Docker Postgres locally if you need concurrency.                                 |
| D2  | **`prisma dev` ignores custom ports**             | The test database runs on the port `prisma dev` assigns to the second server (51219 here). Check with `npx prisma dev ls` and adjust `DATABASE_URL_TEST`.                                                                     | Docker Postgres on a fixed port.                                                     |
| D3  | **Slow seed locally**                             | ~1.5 min for 160 customers, because every order goes through the real ingestion pipeline on a single connection.                                                                                                              | Acceptable: the seed doubles as a pipeline test.                                     |
| D4  | **Integration tests run serially**                | They share one database and truncate tables between tests.                                                                                                                                                                    | One schema per worker if the suite grows.                                            |
| D5  | **Storefront automation is fragile**              | `npm run shopify:abandon` creates abandoned checkouts by driving the real storefront and checkout with Playwright (there is no Admin API mutation for them). Changes to Shopify's checkout UI or bot protection can break it. | Re-check the selectors when it fails, or create the carts by hand in the storefront. |
| D6  | **Shopify CLI store tokens expire**               | `npm run shopify:populate` uses the online token stored by `shopify store auth`; when it expires the script fails and asks to authenticate again.                                                                             | Re-run `shopify store auth`; for CI, an app with an offline token.                   |
