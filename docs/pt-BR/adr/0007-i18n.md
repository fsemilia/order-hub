# 0007 — Três idiomas de interface com segmento raiz escolhido por cookie

🌐 [English](../../en/adr/0007-i18n.md) · **Português** · [Italiano](../../it/adr/0007-i18n.md)

- **Status:** aceita
- **Data:** 2026-11-09

## Contexto

A interface precisa estar em inglês (padrão), português e italiano. É um painel autenticado: sem
SEO, e URLs como `/customers` já são usadas em links, redirecionamentos e testes. O Cache
Components precisa continuar pré-renderizando um shell estático.

## Decisão

- Todas as páginas ficam em `app/[locale]` (layout raiz, `generateStaticParams` para os três
  idiomas), como no guia de internacionalização do Next.js, então cada idioma tem seu shell
  pré-renderizado.
- As URLs continuam **sem prefixo**: o `proxy.ts` reescreve `/customers` para
  `/<locale>/customers` a partir do cookie `oh_locale` (padrão `en`). `/it/...` define o cookie uma
  vez e redireciona, então um link ainda pode escolher o idioma.
- Dicionários tipados em `lib/i18n/dictionaries` (o inglês é o tipo de referência, uma chave
  faltando quebra o typecheck; um teste unitário confere chaves e placeholders). Server Components
  usam `next/root-params`; Client Components recebem o dicionário de um provider; Server Actions
  leem o cookie (root params não estão disponíveis ali).
- Números, dinheiro e datas usam `Intl` com o idioma da interface e a moeda **da loja**.
- O prompt de sistema do agente é em inglês e um bloco separado indica o idioma da resposta.
- Sem biblioteca de i18n: três idiomas e algumas centenas de textos não justificam uma.

## Consequências

- (+) Nenhum link ou redirecionamento mudou; o shell estático é pré-renderizado para cada idioma.
- (+) Traduções erradas são pegas cedo (tipos + teste), não em produção.
- (−) Trocar de idioma recarrega a página; o idioma não fica na URL:
  [limitations.md](../limitations.md), itens U2 e U4.
